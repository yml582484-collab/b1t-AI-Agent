## 1. 文档概述

### 1.1 文档目的
本文档定义了b1t-AI智能助手产品的核心需求、功能规格、用户场景及商业化路径，为开发团队、测试团队和运营团队提供统一的产品认知。

### 1.2 产品定位
**一句话描述**: 面向开发者和企业用户的私有化AI Agent框架，提供超越标准LLM的自主任务执行能力。

**核心价值主张**:
- 对比DeepSeek网页版：不只是"会说话的大脑"，而是"大脑+手+记忆+工具箱"
- 对比Coze/Dify：更轻量、更可定制、完全私有化部署
- 对比LangChain：开箱即用，降低Agent开发门槛

### 1.3 目标用户

| 用户类型 | 占比 | 核心痛点 | 使用场景 |
|---------|------|---------|---------|
| **独立开发者** | 40% | 需要快速构建AI应用原型 | 个人项目、副业开发 |
| **中小企业技术负责人** | 35% | 数据安全要求高，无法使用云端AI | 内部工具、客服系统 |
| **AI产品经理/创业者** | 20% | 需要验证Agent产品概念 | MVP验证、演示Demo |
| **教育/研究人员** | 5% | 需要可解释的AI系统 | 教学演示、学术研究 |

                    高定制化

    LangChain ←——————— b1t-AI ———————→ 企业定制开发

## 4. 产品功能规格

### 4.1 核心功能模块

#### 4.1.1 ReAct推理引擎

**功能描述**: 实现思考→行动→观察→再思考的循环推理机制

**用户价值**: 
- 解决复杂多步骤任务
- 保证数学计算准确性
- 支持错误自我纠正

**技术规格**:
```yaml
最大迭代次数: 8步
超时保护: 120秒
错误恢复: 连续失败3次自动停止
支持模式: 
  - 简单模式: 直接对话
  - ReAct模式: 智能规划执行
```

**使用示例**:
```
用户: 计算斐波那契数列前20项并保存到文件

Agent执行:
Step 1: 思考 → 需要生成数列+保存文件
Step 2: 行动 → 调用code_executor生成数列
Step 3: 观察 → 获得数列数据
Step 4: 思考 → 数据已获取，准备保存
Step 5: 行动 → 调用file_manager保存文件
Step 6: 完成 → 返回结果
```

#### 4.1.2 三层记忆系统

**架构设计**:
```
┌─────────────────────────────────────────┐
│           三层记忆架构                   │
├──────────────┬──────────────┬───────────┤
│   短期记忆    │   长期记忆    │  工作记忆  │
│  Short-Term  │   Long-Term  │  Working  │
├──────────────┼──────────────┼───────────┤
│ 最近10轮对话 │ ChromaDB向量库│ 任务状态  │
│ 滑动窗口     │ 语义搜索     │ 变量追踪  │
│ 自动清理     │ 永久保存     │ 临时存储  │
└──────────────┴──────────────┴───────────┘
```

**技术规格**:
```yaml
短期记忆:
  窗口大小: 10轮对话
  清理策略: LRU自动清理

长期记忆:
  存储引擎: ChromaDB
  检索方式: 向量相似度搜索
  持久化: 本地文件存储

工作记忆:
  用途: 复杂任务状态追踪
  生命周期: 单次会话
  容量: 无限制（内存存储）
```

#### 4.1.3 工具生态系统

**内置工具清单**:

| 工具 | 功能 | 典型场景 | 技术实现 |
|------|------|---------|---------|
| web_search | DuckDuckGo实时搜索 | 获取最新信息、打破知识截止 | HTTP API |
| calculator | 安全数学计算 | 精确计算、数据分析 | Python eval沙箱 |
| code_executor | Python/JS代码执行 | 算法生成、数据处理 | 受限沙箱环境 |
| file_manager | 文件读写管理 | 保存结果、读取配置 | 路径安全检查 |

**扩展机制**:
```python
# 自定义工具示例
from src.tools.base import BaseTool

class DatabaseTool(BaseTool):
    name = "database_query"
    description = "查询MySQL/PostgreSQL数据库"
    
    async def execute(self, sql: str) -> dict:
        result = db.execute(sql)
        return {"success": True, "data": result}
# 自动注册，无需额外配置
```

#### 4.1.4 API服务

**核心端点**:

```yaml
POST /api/chat:
  描述: 发送消息（支持普通/ReAct模式）
  参数:
    - message: 用户输入
    - use_react: 是否启用ReAct模式
    - session_id: 会话ID（可选）

POST /api/chat/stream:
  描述: 流式响应（SSE实时推送）
  特性: 实时显示思考过程和中间结果

GET /api/status:
  描述: Agent状态监控
  返回: Token消耗、内存占用、运行状态

GET /api/tools:
  描述: 列出所有可用工具

POST /api/tools/{name}/toggle:
  描述: 动态启停工具

GET /api/sessions:
  描述: 会话列表

GET /api/usage:
  描述: DeepSeek余额查询
```

### 4.2 非功能需求

#### 4.2.1 性能指标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 简单对话响应 | <5秒 | 非ReAct模式 |
| ReAct任务完成 | 30-60秒 | 取决于任务复杂度 |
| 工具执行延迟 | <1秒 | 本地工具 |
| 记忆检索时间 | <50ms | ChromaDB向量搜索 |
| 并发连接支持 | 100+ | 异步非阻塞IO |

#### 4.2.2 安全要求

- **数据隐私**: 所有数据本地处理，LLM调用可配置
- **访问控制**: API Key认证机制
- **输入过滤**: 危险命令检测、路径遍历防护
- **代码执行**: 沙箱环境，受限权限

#### 4.2.3 兼容性

- Python 3.10+
- 支持Windows/Linux/macOS
- 支持DeepSeek/OpenAI兼容API
